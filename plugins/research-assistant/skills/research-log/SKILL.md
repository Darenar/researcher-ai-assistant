# Research log

Use `research/RESEARCH_LOG.md` unless the project configuration specifies another path.

- Append dated entries; do not rewrite prior decisions silently.
- Record the decision or result, rationale, supporting files or commits, assumptions, responsible person when known, unresolved questions, and next action.
- Distinguish observed facts from interpretations and future plans.
- Link to project-relative artifacts and Git commits rather than copying large outputs.
- If a previous decision changes, add a superseding entry that references the earlier entry.

Do not log secrets, API keys, personal data, or raw-data contents. Ask before creating the log when the user requested only a status report.
